# Fusion Analysis: Design Decisions

## Purpose

Combining the subject-level GNN and the strongest tabular baseline via late fusion to test whether EEG connectivity provides complementary predictive signal for APOE ε4 classification beyond what tabular features already capture.

## Motivation

Standalone results at the end of the modelling phase were:

- **Subject-level GNN (tuned):** mean AUC 0.655 ± 0.207 (best fold 0.950)
- **logistic_compact_full baseline:** mean AUC 0.830 ± 0.065

The GNN achieved peak performance matching the tabular baseline in some folds, suggesting real signal. Whether this signal is complementary to tabular features or redundant with them is an empirical question that fusion answers directly.

## Design decisions

### Decision 1: Late fusion via weighted averaging (primary), meta-learner (secondary)

Combining the two models' probability outputs rather than their internal representations.

- **Weighted averaging:** `fused_prob = w_gnn * gnn_prob + w_tab * tab_prob`. Simple, interpretable, avoids overfitting risk at N=74.
- **Meta-learner:** logistic regression on the two probability streams. Slightly more sophisticated; will report if it gives a different picture than weighted averaging.

Late fusion was chosen over intermediate fusion (concatenation of learned representations) because:

1. At N=74, additional parameters from a fusion MLP are a significant overfitting risk
2. Late fusion preserves interpretability — the fusion weights themselves become a research finding
3. Late fusion is standard and well-established in the multimodal machine learning literature
4. Intermediate fusion can be added as a later extension if time permits

### Decision 2: Choice of tabular baseline — logistic_compact_full

Selected from six candidate baselines (three model types × two feature-set variants) based on four criteria:

1. **Strongest standalone performance:** mean AUC 0.830, highest of all six
2. **Tightest confidence interval:** std 0.065, tightest of all six
3. **Preserves interpretability:** logistic regression coefficients are directly readable
4. **Product of thoughtful feature engineering:** the compact feature set reflects EDA-driven curation of blood, CVLT, and personality features

Alternative candidates considered:

- `logistic_compact_light` (N=79, AUC 0.744) — larger cohort but 0.086 lower AUC
- `lasso_all_full` (N=76, AUC 0.735) — data-driven but weaker performance
- Random forest variants — high variance, less interpretable

### Decision 3: Cohort alignment — intersection of GNN and tabular cohorts

Fusion requires both models to make predictions on the same subjects. Given:

- GNN cohort: N=77 (excludes sub-55 for missing rest data, sub-69 for no consent)
- logistic_compact_full cohort: N=76 (additionally excludes 3 subjects — sub-53, sub-68, sub-79 — with missing blood panel data)

The intersection cohort has N=74 subjects. 43 carriers (58.1%), 31 non-carriers (41.9%). This cohort is used for all fusion experiments. Both models are retrained on this exact cohort so predictions are directly comparable.

The intersection choice preserves methodological rigour but slightly reduces sample size compared to running either model alone. This trade-off is necessary for valid fusion.

### Decision 4: Shared cross-validation splits

Both models use a single canonical set of 5-fold splits stored in `data/shared_cv_splits.json`. Generated by `scripts/generate_shared_splits.py` using `StratifiedGroupKFold` with:

- Groups = subject IDs (prevents subject leakage per Brookshire et al. 2024)
- Stratification = APOE ε4 labels (ensures balanced carrier/non-carrier ratios per fold)
- Random state = 42 (matches the seed used across the rest of the project)
- 5 folds (matches the tabular baseline's original CV configuration)

Loading pre-computed splits eliminates the possibility of the two models using different fold assignments, which would produce fusion results that are not statistically valid. Both `scripts/rerun_tabular_for_fusion.py` and the Colab GNN notebook load from the same JSON file.

### Decision 5: Fold-aware imputation and standardisation

For the tabular baseline rerun, imputation and standardisation are fit on training data only within each CV fold, then applied to both training and validation. This differs from the original baseline where preprocessing was computed on the full cohort before CV.

Rationale: fitting preprocessing on the full cohort implicitly leaks information from validation into training. In a small-N study, this can inflate performance estimates. Fold-aware preprocessing produces more conservative but methodologically valid AUCs.

The impact of this change was measurable — the fusion-ready `logistic_compact_full` achieved AUC 0.771 versus the original 0.830. The 0.06 drop is consistent with published effect sizes for information leakage in small samples and represents the more trustworthy performance estimate.

### Decision 6: Report fusion weights as findings

Rather than treating fusion weights as internal parameters, they are reported as research findings. Fusion weights answer a specific scientific question: how much predictive signal does each modality provide when both are available?

The fusion writeup will report:

- Optimal weights from grid search
- Per-fold optimal weights (for stability check)
- Plot of combined AUC as a function of GNN weight
- Interpretation in the context of the specific task

### Decision 7: Report both original and fusion-ready tabular baselines

For transparency, both versions of the tabular baseline are reported:

- **Original:** AUC 0.830, cohort N=76, preprocessing on full cohort (existing dissertation writeup)
- **Fusion-ready:** AUC 0.771, cohort N=74, fold-aware preprocessing (this analysis)

The 0.06 gap represents the methodological correction and is acknowledged as a valid improvement in rigour rather than a performance regression.

## Implementation

Three new files created in Phase 1-2:

- `scripts/generate_shared_splits.py` — produces the canonical CV splits
- `src/agnn/baselines/data_processing_shared.py` — fold-aware data loading
- `src/agnn/evaluation/cross_validate_shared.py` — CV with shared splits and fold-aware preprocessing
- `scripts/rerun_tabular_for_fusion.py` — driver for the fusion-ready tabular baseline

Original code (`data_processing.py`, `cross_validate.py`, `train_baselines.py`) is unchanged. The fusion-ready code is parallel to the original for direct comparison.

## When to revisit

Adjust the fusion approach if:

1. **Weighted averaging produces AUC ≤ 0.83** — no complementary signal captured. Report the null result and skip intermediate fusion
2. **Weighted averaging produces AUC 0.83–0.87** — modest improvement. Meta-learner may add a further 0.01-0.02
3. **Weighted averaging produces AUC 0.87+** — meaningful improvement worth investigating with intermediate fusion or feature importance analysis

## Limitations of this fusion approach

Three limitations to acknowledge:

**1. Small cohort limits statistical power.** With N=74 and 5-fold CV, each validation fold has ~15 subjects. Fusion results share the same high-variance property observed in the standalone models.

**2. Weights depend on the training cohort.** Fusion weights are optimised for the N=74 intersection cohort. Different cohorts might yield different optimal weights.

**3. Late fusion cannot learn cross-modality interactions.** A GNN pattern that only becomes predictive when combined with a specific tabular feature is invisible to late fusion. Intermediate fusion is required to capture such patterns.
