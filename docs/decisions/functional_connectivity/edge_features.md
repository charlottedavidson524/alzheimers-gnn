# Edge Features

Needed to decide what values each edge carries, and how multi-band wPLI information enters the graph

Each edge in the graph is a wPLI value between two electrodes. With bands and a fixed 127-node topology already decided, the remaining question is how per-band wPLI values attach to each edge: a single scalar (one band, or one already-combined value), or a richer per-edge structure carrying information from multiple bands at once.

In frequency-bands.md it was proposed that for the default for combining bands, that "each edge carries a length-5 vector of per-band wPLI values on the same 127-node topology." Have now researched how GNN architectures actually consume edge info and frequency bands proposal needs to be revised. Its incompatible with the default architecture.

standard Graph Convolutional Network (Kipf & Welling, 2017) which underlies Klepl et al. (2022) which was used as a precedent for frequency bands, edge thresholding and graph-aggregation.md — only consumes a single scalar weight per edge (the entries of the adjacency matrix), not a multi-dimensional edge feature vector. The original paper states this directly within the limitations section: "Our framework currently does not naturally support edge features and is limited to undirected graphs (weighted or unweighted)" (Kipf & Welling, 2017, Section 7.2). This is supported by Gong & Cheng (2019). they note in their related-work review that "GCNs can utilize one-dimensional real-valued edge features, e.g., edge weights, but the edge features are restricted to be one-dimensional". Architectures that do support genuine multi-dimensional edge features would be GAT variants with edge-attribute support, NNConv, GINEConv, EGNN (Gong & Cheng, 2019), R-GCN (Schlichtkrull et al., for typed/multi-relational edges), ME-GCN (Wang et al., 2022). These are a different, more complex layer type than plain GCN.

So, committing to a length-5 (or length-6, per the current band count) per-band edge vector the way was originally proposed in frequency bands is also a commitment to switching the GNN architecture away from standard GCN. That's a bigger decision than a data-encoding choice. Avoid doing this for now.

Every EEG-GNN paper surveyed in this project's other decision docs that uses multiple frequency bands handles it the same way. As parallel per-band graphs (or "streams"/"branches"), each with standard scalar edge weights, fused after the graph-convolution stage rather than as a single graph with vector-valued edges.

Klepl et al. (2022) compute a separate brain graph, and separately trained/selected GNN configuration, per frequency band (their band sweep across delta/gamma/alpha etc is reported as which single band performed best per model type (alpha for the best GNN, theta for baselines) rather than as bands fused within one model).
Xu et al. (2025, MF-MGCN) (already covered in node- features section) builds one graph per frequency band (5 parallel graph-convolution branches, each a standard 2-layer GCN with scalar-weighted adjacency matrices -> one functional, Pearson-correlation-based and one structuralwith same-region binary), with band-specific outputs concatenated only at the fully-connected classification layer, after graph convolution is complete. This is a direct, task-matched precedent. Multi-band information is preserved by running the GCN separately per band and fusing late, not by giving each edge a multi-band feature vector.

ME-GCN (Wang et al., 2022), a general (non-EEG) multi-dimensional-edge GCN formalizes this exact pattern as "multi-stream" GCN: T separate adjacency matrices (one per edge-feature dimension in this case, one per band), each processed by its own GCN stream sharing the same input node features, with streams combined afterward. This is a generalized, named version of exactly what Klepl et al. and Xu et al. do in practice for EEG.

This pattern (parallel per-band graphs with scalar edges, fused late) is both the standard-GCN-compatible option and the dominant choice in the most comparabale literature.

Decided to use scalar wPLI weight per edge, one graph per band, fused after graph convolution The default is that each edge carries a single scalar wPLI value. Multi-band information enters via one graph per band (matching frequency-bands.md's band set), each processed through its own GCN branch with the same node features (per node-features.md) but band-specific edges and band-specific adjacency (per edge-thresholding.md, applied independently per band or with a shared mask ). Branch outputs are concatenated before the final classification layer, matching Xu et al. (2025)'s "flattening" step.
